# ベース実装の利用・改修ガイド

## 現在の受け入れ条件

商品一覧8件、キーワード検索、カテゴリー／価格／在庫の組合せフィルター、価格／新着順、商品詳細、カート追加／数量変更／削除、税込合計／送料計算、リロード後の保持。PCとスマートフォンで操作できる。検索0件・読込失敗・商品不明・在庫切れが表示される。
比較・お気に入り・お問い合わせ・決済・注文作成はない。Docker実API版では会員ログインとDB保存に対応。

## デモの起点

1. 商品一覧を開く。家具・照明に絞り、商品詳細からカートへ入れる。
2. 「既存サイトの機能が動く」ことを示した後、比較機能などの新しい要望を提示する。
3. Code Layersで扱うコードは `src/features/catalog`、共通部品はnpmの `@mnoritake-figma/ds`（元ソースはDSリポジトリの `src/ui`）。APIは `src/api/client.ts`。
4. Guidelinesへ持ち込む実装ルール: DSの部品とsemantic tokenを再利用する。新しい画面の追加をパッケージ内部の直接改変で行わない。ButtonはonPress、InputFieldはonChange。税込JPY整数、在庫切れ・失敗状態も設計する。
5. Specsへ記載する元仕様は `API.md` と現在の受け入れ条件。新機能の仕様を追加してから実装へ進む。
6. Payload検証環境は [BACKENDS.md](BACKENDS.md) から起動する。Makeとの実接続は別途確認が必要。MSWモードの保存をPayloadの保存と説明しない。

## 次の機能に進むときのプロンプト例

「このリポジトリのdocs/DESIGN-SYSTEM.mdとdocs/API.mdを読み、既存の一覧・検索・カートを維持したまま、Specsで合意した比較機能を追加してください。npmパッケージの元コンポーネントは改変せずに再利用し、比較の選択上限・空状態・モバイルの操作を定義してテストしてください。」

これは次の作業用の例であり、本実装には比較機能を追加していない。

## 準備するもの・ユーザー操作

- GitHubリポジトリ: `mnoritake-twigma/demo-shopping`。既存DSリポジトリに混ぜない。
- 初期ベースをmainへ置き、改修作業は `codex/ec-baseline`、デモの新機能は別ブランチに分ける。
- ユーザーが作成したGitHubリポジトリへベース実装を配置。追加変更はREADME記載のremoteへpushする。
- 新しいCodexチャット／追加プロンプトは起動に不要。このフォルダーをプロジェクトとして開けばよい。
- Figmaの接続対象には新しいECリポジトリを選ぶ。DSのCode Connect公開と、Make等で利用するコードソース設定は別。既存の接続を自動的に切り替えていない。
- PayloadはローカルDocker構成を用意済み。Figmaの新規ファイル、Specsの実ファイル、Guidelines設定、Make接続は未作成・未検証。
- カートをリセットするにはカート画面で商品をすべて削除する。MSWモードはブラウザ間で共有しない。実API版では同じ環境・同じ会員でログインすると共有される。

## デモ上の前提

写真・名称・価格・在庫・素材は架空のカタログ。写真は見本で、販売物の正確な仕様を表していない。ログインには架空の検証アカウントを使用する。
